# 听译记

> 英文课堂实时转写、双语翻译与结构化笔记

听译记是一个面向个人学习和朋友共享的开源桌面工具，不是商业服务。项目采用 [MIT License](LICENSE)，支持 Windows RTX 本地识别和 Apple 芯片 Mac 的 MLX 本地识别；翻译、实时摘要和课堂整理可以使用用户自己配置的 DeepSeek API。

> 使用前请遵守学校规定、课程版权和所在地的录音与隐私法律，并在需要时获得老师和其他参与者的同意。不要把包含 API Key、个人课堂录音或课件的文件提交到公开仓库。

## macOS（Apple 芯片）

Mac 版与 Windows 版共用界面、课程库、DeepSeek 翻译、实时总结和导出格式；语音识别会自动改用 Apple MLX。当前优先支持 M1、M2、M3、M4 及更新的 Apple 芯片，线下课堂直接使用 Mac 麦克风。

首次安装：

1. 安装 Python 3.11 或更新版本；导入 MP3/MP4 还需要 `ffmpeg`。
2. 在终端进入项目目录，执行 `chmod +x ./*.command`。
3. 双击 `安装听译记-macOS.command`，完成后双击 `启动听译记-macOS.command`。
4. 在“设置”中选择 Mac 本地模型，点击“下载并预热模型”；完成后会显示 MLX 环境和可用麦克风数量。
5. 第一次测试音源或开始课堂时，允许终端或听译记使用麦克风。模型下载约 1.6 GB，之后从本机缓存读取。
6. 在“设置”中填写 DeepSeek API Key。英文识别留在 Mac 本地，DeepSeek 只接收需要翻译和整理的文字。

默认模型为 `mlx-community/whisper-large-v3-turbo`；内存较小或希望更快启动时，可在设置中选择 `mlx-community/whisper-large-v3-turbo-8bit`。若要制作给别人一次下载的安装盘，运行 `构建听译记-macOS.command`，产物为 `dist/听译记-macOS-AppleSilicon.dmg`。

目前 Mac 第一版专注线下课堂麦克风。macOS 的“系统声音直采”没有沿用 Windows WASAPI，需要以后单独接 ScreenCaptureKit；这不影响线下听课。Intel Mac 可以使用云端实时语音，但不支持 MLX 本地模式。

如果 Mac 上启动失败，`启动听译记-macOS.command` 会在项目目录生成 `听译记-启动日志.log`。反馈问题时保留这份日志即可，不要把 `.env` 发给别人，因为其中包含 API Key。

听译记可以使用麦克风实时记录英文课堂，也可以导入已有英文音频或视频文件。软件会生成英文原文、中文翻译和结构化 Markdown 笔记，并把处理结果保存到本地 SQLite。

当前版本有两个入口：

- `classnote-gui`：桌面图形界面，支持实时课堂、文件转写、课程库与配置查看；
- `classnote process`：命令行处理真实音频；
- `classnote demo`：不调用 API，用内置英文文本验证存储与导出流程。

## 1. 安装

建议在 PowerShell 中运行：

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
```

打开软件的“设置”，默认选择 RTX 本地英文识别，再填写自己的 DeepSeek API Key。
这样实时课堂和文件转写都不需要语音 API Key；密钥只保存在本机，`.env` 已被 Git 忽略。

## 2. 先运行离线演示

```powershell
classnote demo --title "计算机网络演示课"
```

演示不会上传内容，也不会产生 API 费用。生成结果位于 `exports`，数据库位于 `data/classnote.db`。

## 3. 启动图形界面

```powershell
classnote-gui
```

安装完成后，也可以直接双击项目根目录中的 `启动听译记.bat`。

新版界面采用左侧导航和课堂工作区布局：

- “首页”用于快速开始实时课堂或导入录音，并显示最近课程；
- “实时课堂”集中显示输入设备、临时字幕、英中对照记录和录音控制；
- “文件转写”支持点击选择或拖放音视频文件；
- “课程库”可以搜索历史课程并查看笔记；
- “设置”可以直接选择转写、翻译与整理服务和模型，并安全地保存本机 API 密钥；不需要手动编辑 `.env`。

### 图形化配置

进入“设置”后：

1. 在“课堂语音转写”中选择“本地 RTX 实时识别”；
2. 为中文翻译选择 DeepSeek 并粘贴 API Key；
3. 选择推荐模型，或直接输入账户支持的模型名称；
4. 点击“保存并应用”。

“笔记输出位置”可以选择任意本机文件夹，也可以直接输入一个尚不存在的目录；保存设置时软件会自动创建它。之后实时课堂和文件转写生成的 Markdown 笔记都会写入该位置，历史课程数据库仍保留在原位置。

本地识别会使用 NVIDIA CUDA，不会上传英文音频；模型首次使用自动下载，之后从本地读取。
选择 DeepSeek 时只需要粘贴 DeepSeek API Key，服务地址会自动配置。若改用 OpenAI 云端语音，才需要填写 OpenAI API Key。

### 实时课堂

1. 在设置中选择本地 RTX 识别，并配置 DeepSeek API Key；
2. 填写课程名称和课程领域；
3. 在“输入设备”中选择麦克风；
4. 点击“开始实时课堂”；
5. 默认使用本地 GPU：界面先显示英文临时字幕，句子稳定后立即保存，并由 DeepSeek 流式翻译；
6. 可以暂停和继续；
7. 点击“结束并整理”，等待最后片段处理完成并生成整节课笔记。

实时课堂采用三栏工作台：左侧关联 PDF、PPTX、DOCX、TXT 或 Markdown 课程资料，中间上方显示当前英文原文、中间下方显示中文翻译及历史记录，右侧每积累数句已确认字幕后在后台生成一次滚动主题、关键要点、术语和待复习问题。滚动摘要与逐句翻译使用独立线程并设置较短超时，不会阻塞字幕；摘要失败也不影响英文保存和中文翻译。并发翻译即使完成顺序不同，顶部仍只显示最新一句；向上滚动阅读旧内容时软件会暂停自动跟随，并显示“回到最新”。软件会从课件提取英文关键词、缩写和形如“English term：中文术语”的对照表；精简后的热词会提示本地 Whisper，中英术语表会传给 DeepSeek，提高专业课程的识别与翻译一致性。旧版 PPT/DOC 请先另存为 PPTX/DOCX。

课堂阅读区分为三层：固定在顶部的“老师正在讲”显示当前英中字幕；“最近几分钟”在本地合并最近两分钟内最多 12 句稳定中文，并在滚动摘要就绪后使用当前主题作为标题；下方完整课堂记录继续按照自然停顿和转场语句合并成段落。历史段落默认突出中文，英文原文和逐句时间轴按需展开，因此快速回顾不需要在大量双语单句之间来回寻找。两个回顾区按时间增量索引字幕，长课中只读取最近窗口；即使字幕晚到，也按课堂时间排序。若最近两分钟的中文仍未完成，界面不会把很久以前的译文误当作“刚才内容”。这些回顾完全复用本地记录，不会新增 API 请求或费用。

底部“回顾刚才”可随时展开最近 30 秒、1 分钟或 2 分钟的已保存内容，查看英文原文，或跳到对应的完整段落。通过课堂脉络、手动标记或快捷回顾跳到旧段落时，目标段落会短暂高亮，记录区随即出现“回到实时”；手动向上滚动也会出现该入口。长课只把最近约 160 个段落实例化为界面卡片，更早记录仍完整保存在本机，可以用记录区的“更早 / 较新”翻页，或直接从主题和标记跳转。密集字幕会合并安排界面自动跟随，不会为每句重复排一个滚动定时任务。阅读旧内容期间，新字幕不会把页面抢回底部；中文尚未返回的片段会明确显示已保存的英文。点击“回到实时”或在课堂工作区按 `End` 可回到最新记录。回顾只是本地字幕摘录，不额外调用模型，也不会把摘录冒充成 AI 总结。

课堂底部可切换“中文优先 / 双语对照 / 英文优先”三种阅读模式。中文优先默认收起历史英文；双语对照同时展示两种语言；英文优先让当前和历史英文成为主要阅读内容，中文仍保留作核对。切换只改变本机界面显示，不会更改已保存的课堂原文或译文，也不会增加 API 调用；选择会写入本机 `.env`，下次启动继续使用。

课堂质量条中的“已保存 N 句”表示这些英文字幕已经写入本地课程库，不需要等待中文翻译完成。右侧会显示摘要的“积累中、正在整理、刚刚更新”状态。为防止误触，底部“结束并整理”需要在 4 秒内再次点击确认；确认期间课堂仍会继续记录，超时后自动取消，不会弹出阻塞课堂的对话框。

听到关键内容时，可以点击底部“重点”或按 `Ctrl+1` 标记当前句；需要课后追问或复习的内容可以点击“疑问”或按 `Ctrl+2`。再次使用同一标记会取消。读到较早的段落时，可用段落右上角“标记”菜单补标该段最后一句；右侧“手动重点与疑问”会显示标记前后约 20 秒的语境，点击标记标题可跳回完整记录。标记会立即写入本地课程库，并显示在实时段落、课程库预览和导出的 Markdown 笔记中；最终整理时也会把手动重点和疑问提供给模型。某句中文在自动重试后仍失败时，该段右上角会出现“重试失败”，课堂进行中即可重新提交，不会新增重复字幕。

本地 RTX 模式点击开始后会先打开麦克风，再在后台加载 Whisper。模型准备期间，顶部会明确显示“音频已开始采集”和已缓存秒数；开场音频最多可在内存中缓存约 5 分钟，模型就绪后会从 00:00 开始处理，不会把延迟识别的开场内容误记到模型加载完成的时间。已加载的本地模型会在本次软件运行期间复用，下一节使用相同模型的课堂无需再次完整加载；切换模型时只保留一个 GPU 模型，避免持续占用显存。

开始课堂后，左侧显示“课堂脉络”时间轴。低频滚动摘要出现稳定的新主题时，软件自动记录主题及时间；点击主题可以跳到相应的历史段落，向上阅读不会被新字幕抢走位置。主题会保存在本地课程库，课后查看该课程和导出的 Markdown 时也能看到按时间排列的主题；未生成主题的课程不会出现空白章节。导入课件后，可用底部按钮在“课堂脉络”和“课件”之间切换；未导入课件也不会出现空白课件栏。时间轴复用已有摘要，不会增加 API 调用。开始课堂会自动进入全屏专注模式，隐藏顶部导航和页面标题；按 `Esc` 只退出全屏，录音、识别和翻译会继续运行。

稳定英文会在调用 DeepSeek 之前写入 SQLite。网络断开或翻译失败不会丢失英文；翻译状态也会保存，便于稍后补译。整理出的笔记会先作为草稿保存，Markdown 导出完整写入后课程才标记为“已完成”；重新导出会先写临时文件再替换，失败时保留原笔记文件。
课程库会标出“需要处理”和待补译句数，选择课程后可点击“补译并整理”恢复中文、重新生成笔记并刷新导出文件。软件异常退出后，上次仍在录制、识别、翻译或整理的课程会标记为“上次中断”，不会伪装成已完成。

关闭正在录课的窗口时，听译记会先停止录音、保存最后字幕并等待后台收尾，完成后才退出。启动器采用单实例保护；重复双击会提示返回已经运行的窗口，避免两个实例争用麦克风和显存。

默认配置如下：

```dotenv
LIVE_MODE=local
LOCAL_TRANSCRIPTION_MODEL=distil-large-v3
LOCAL_COMPUTE_TYPE=float16
LOCAL_REFRESH_MS=800
```

在 RTX 4060 8GB 上推荐 `distil-large-v3 + float16`。软件使用 30ms 音频帧、VAD 断句和增量识别，并在课堂界面显示实时 RTF。

如果希望使用云端 Realtime，可以切换：

```dotenv
LIVE_MODE=realtime
OPENAI_API_KEY=你的OpenAI密钥
LIVE_TRANSCRIPTION_MODEL=gpt-live-transcribe
LIVE_TRANSCRIPTION_DELAY=low
```

如果网络或账户暂时不能使用 Realtime 模型，可以切换回兼容分段模式：

```dotenv
LIVE_MODE=chunked
LIVE_CHUNK_SECONDS=10
```

建议设置为 8～20 秒。时间越短，字幕更新越快，但 API 请求次数越多；时间越长，上下文更完整，但等待时间也更长。

### 记录线上课程或电脑声音

课堂准备区会把音源分成两类：

- **麦克风**：适合教室、讲座和面对面授课。
- **系统声音**：直接采集电脑正在播放的网课、会议或视频声音，不需要启用“立体声混音”。系统声音直采使用本地 RTX 实时识别。

开始前先选择音源并点击“测试音源”。软件会录取约 1.8 秒用于检测音量，只显示峰值和平均电平，不保存测试音频。测试麦克风时请正常说一句英文；测试系统声音时请先播放课程音频。界面会提示静音、音量过低、合适或过载。

系统声音会包含电脑发出的所有声音。正式上课前建议关闭通知音、音乐和其他会发声的软件。播放设备如果在课堂中途被切换或断开，软件会提示采集中断，已经写入的字幕仍会保留。

### 课堂运行状态

开始课堂后，字幕区上方会出现一条紧凑的运行状态栏：

- **音源**：显示实时输入电平。连续 8 秒没有有效声音会提示“安静”，20 秒后标红为“静音”；输入削波时提示“过载”。
- **识别**：本地 RTX 模式显示单次推理耗时以及“流畅 / 正常 / 正在追赶”。
- **翻译**：显示实时、处理中或等待翻译的句数；积压 3 句开始提醒，积压 8 句标红。
- **音频完整性**：正常显示“音频完整”；电脑处理不过来时显示累计丢帧毫秒数。

短暂停顿属于正常情况，不会立刻报警。状态栏只用于运行监测，不会改变或删除已经保存的英文字幕。

选择 `.mp3`、`.wav`、`.m4a`、`.mp4`、`.mpeg`、`.mpga`、`.ogg`、`.webm` 或 `.flac` 文件，填写课程名称，然后开始处理。
文件处理会先创建可恢复的课程任务，Whisper 每产生一条英文就立即保存，再用两个并发翻译任务保持每条英文与中文一一对应。翻译或整理失败时，已经完成的英文不会丢失，可从课程库继续处理。

## 4. 命令行处理

```powershell
classnote process "D:\课堂录音\lesson1.mp3" --title "计算机网络 第一课" --subject "计算机网络"
```

如果课堂中有特殊术语，可以多次添加：

```powershell
classnote process lesson.mp3 --title "操作系统" --term "thread=线程" --term "race condition=竞态条件"
```

## 隐私提醒

真实处理模式会把选择的音频和转写文本发送给所配置的云端 API。使用前请取得教师和相关人员许可。当前版本不会复制或长期保存原始音频；SQLite 中保存的是转写、翻译、笔记和原始文件路径。若课程含敏感信息，请不要直接使用云端模式。

## 使用 DeepSeek 翻译和整理

默认方案使用本地 faster-whisper 完成英文识别，DeepSeek 只负责中文翻译和笔记：

```dotenv
LIVE_MODE=local
TEXT_PROVIDER=deepseek
DEEPSEEK_API_KEY=你的DeepSeek密钥
TEXT_MODEL=deepseek-v4-flash
```

`deepseek-v4-flash` 适合逐句翻译和普通笔记整理。程序会关闭思考模式以减少实时字幕等待时间。如果希望课后整理使用更强模型，目前也可以将 `TEXT_MODEL` 改为 `deepseek-v4-pro`，但这会同时影响逐句翻译的延迟和费用。

DeepSeek 当前提供文本模型，不负责麦克风语音识别；本软件通过本地 RTX 运行 faster-whisper 补齐这部分，因此默认方案只需要一个 DeepSeek Key。

## 使用其他 OpenAI 兼容文本服务

通用配置格式：

```dotenv
TEXT_PROVIDER=compatible
TEXT_API_KEY=服务密钥
TEXT_BASE_URL=https://服务地址/v1
TEXT_MODEL=模型名称
```

本地兼容服务也可以这样配置，例如：

```dotenv
TEXT_PROVIDER=compatible
TEXT_API_KEY=local
TEXT_BASE_URL=http://localhost:11434/v1
TEXT_MODEL=qwen3:8b
```

兼容模式要求服务实现 OpenAI 风格的 `/chat/completions`。不同服务对 `base_url` 是否包含 `/v1` 的要求不同，应以对应服务文档为准。

## 当前范围与下一阶段

当前默认使用 RTX 本地增量识别，并保留 OpenAI Realtime 与分段云端模式作为备用。英文识别、SQLite 保存、DeepSeek 流式翻译和最终整理分别运行；稳定英文先保存，临时字幕不会污染正式笔记。
